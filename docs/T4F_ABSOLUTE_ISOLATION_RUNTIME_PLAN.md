## 0. 本フェーズが証明しようとしているもの

ロードマップ §7 が言葉を与えている。

> 証明するのは「同期が失敗する」ことではなく「**同期という概念が binary に存在しない**」ことである。

静的走査（T4-B / T4-D）は**バイナリに何が入っているか**を測った。T4-F が測るのは**動いている間に何が出ていくか**である。

## 1. §15.2 の 4 条項と、現在の充足状況

| # | 条項 | 現状 |
|---|---|---|
| 1 | archive に socket/DNS/Network.framework/entitlement/network plist キー等が 0 | **充足**（`ios_archive_scan.sh` S-1〜S-5・実アーカイブ `ALL GREEN` exit=0） |
| 2 | **runtime port scan・全 interface packet capture・symbol/capability/permission scan で app-owned network byte が 0** | **未実施** ← **T4-F の本体** |
| 3 | **機内モードで全機能が完走**（記録・consult・推論・import・archive export/import） | **未実施** |
| 4 | App Store 説明・privacy 回答が offline を正確に表現 | 対象外（提出時） |

**T4-F の射程は 2 と 3 である。** 1 は既に緑で、CI が毎回守っている。

---

## 2. **最重要の設計判断 —— 機内モードでのキャプチャは空虚な緑である**

条項 2 と 3 は**同じ実行で満たしてはならない。**

機内モードには interface が無い。**そこでパケットを捕らえて 0 バイトだったとしても、それは「アプリが喋らなかった」ことを一切証明しない。** 捕らえる媒体が無かっただけである。

**ロードマップ自身が既にそう書いている**（§12.4）。

> **Wi-Fi/Bluetooth/cellular **on** 時も、全 interface packet capture で app-owned network byte が 0**

したがって二つは**別々の試験**である。

| 試験 | 無線 | 証明するもの |
|---|---|---|
| **A: パケットキャプチャ** | **ON（必須）** | 喋れる状況で**喋らない** |
| **B: 機内モード完走** | OFF | ネットワークを**必要としない** |

> **A を機内モードで走らせるのは、テキストファイルで Mach-O スキャナの陽性対照を取るのと同じ誤りである。** 本フェーズで三度見た型——**対照の入力クラスが本番と違う**——の四例目になる。

---

## 3. **キャプチャには陽性対照が要る**

これが T4-F の中核である。

```
「0 バイト捕捉」  と  「キャプチャが動いていなかった」  は、ログ上で区別が付かない。
```

**沈黙は証拠ではない。** したがって各キャプチャ実行は、以下を同一セッション内で示さなければならない。

1. **陽性対照** — 同じ interface 上で**意図的に発生させたトラフィック**（別アプリの通信等）が**捕らえられていること**
2. **その上で** 対象アプリ由来のバイトが 0 であること

**対照が発火しないキャプチャの 0 は、報告してはならない。** `ios_archive_scan.sh` の陽性対照と同じ規律を、実機計測に持ち込む。

## 5. タスク分解

### T4-F-1 — 計測環境の確立と、**その計測環境の陽性対照**

1. USB 接続 → `rvictl -s <udid>` で仮想 interface を起こす
2. `tcpdump` で全 interface を捕捉できることを確認
3. **陽性対照**: 意図的なトラフィックを発生させ、**捕らえられることを実証**

**3 が通るまで、対象アプリの計測を始めるな。** 捕らえられない装置で 0 を数えても意味がない。

### T4-F-2 — port scan の手段確定

`nmap` が無い。代替（`nc` による範囲スキャン等）を決め、**開いているポートを検出できることを陽性対照で示す**。デバイス上で意図的に listen させて検出できるか。

### T4-F-3 — 試験 A：無線 ON でのキャプチャ

全機能を一巡させながら捕捉し、**app-owned バイトが 0** であることを示す。陽性対照を同一セッションに含める。

**「アプリ由来」の判定基準を先に定義せよ。** プロセス単位で切れないなら、切れない範囲を明示する——**測れないものを 0 と書かない。**

### T4-F-4 — 試験 B：機内モード完走

記録・consult・推論・import・archive export/import を機内モードで完走させる。**各機能の完了判定を事前に定義**すること（「クラッシュしなかった」は完走ではない）。

### T4-F-5 — symbol / capability / permission scan（ランタイム側）

静的走査で済んでいる部分と、**実行中でなければ測れない部分**を切り分ける。重複は避け、追加で得られるものだけを測る。

## 8. 本フェーズの成否を分けるもの

T4-D は「接続を主張するなら赤くできる場所に置け」を実証した。T4-E は「その計器はそもそも赤くなれるのか」を問うた。

**T4-F が扱うのは、赤を出せない計器の最も自然な形である——沈黙。**

パケットキャプチャの出力が空であることは、**アプリが静かだったのか、計器が動いていなかったのか**を区別しない。実機計測には CI のような再実行可能性が無く、**その場で対照を取らなければ、後から取り返せない。**

**測っていないものを 0 と書かない（鉄則 2）が、本フェーズでは最も厳しく効く。**
