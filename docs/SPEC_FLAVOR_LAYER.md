## 1. 目的とスコープ

### 1.1 Fact と Flavor

| | **Fact（決定論コア）** | **Flavor（非決定論表現）** |
|---|---|---|
| 産出 | コードのみ。同一入力 → 同一出力 | LLM。同一入力でも揺らぐ |
| 内容 | 数値・状態・判定・スコア | **散文のみ** |
| 権威 | あり（永続化・再注入・分析対象） | **なし**（表示限り・使い捨て） |
| 欠落時 | 動作不能 | **既定動作**（固定テンプレート） |
| 検証 | 契約テスト・リプレイ恒等性 | ガード通過 or 破棄 |

### 1.2 受入基準

> **フレーバ層を丸ごと削除しても、アプリは完全に使用可能であり、権威状態はバイト単位で同一でなければならない。**

これを満たさない設計は、名称が何であれフレーバ層ではない。フレーバが「無いと困るもの」になった時点で、非決定論がコアへ侵入している。

### 1.3 射程（FLV-R-1）

**含む**: 決定論的に確定した Fact に対し、LLM が**言い回しのみ**を与える経路。初回適用先は BLACKBOX アリーナのイベント文言。

**含まない**: CONSULT の応答、面接対話、ES 添削、講評本文。これらは **LLM が主機能そのもの**であり、LAW-19 / no-llm-authority で既に律されている。

> **FLV-W-01（最大の罠）**: 「LLM が化粧」の面と「LLM が本体」の面を混同すること。前者に本機構を被せないと壁が漏れ、後者に被せると機能が壊れる。射程の拡大は必ず裁定を経ること。

## 2. 設計公理

| ID | 公理 | 根拠 |
|---|---|---|
| **A-1 削除可能性** | フレーバ層は削除可能。LLM 不在は劣化ではなく既定 | SPEC_BLACKBOX §14 |
| **A-2 数値発明の禁止** | 出力中の全数値表現は入力 slot 集合に含まれること。含まねば**破棄**（修正・再試行ではない） | SPEC_BLACKBOX §14 / LAW-19 |
| **A-3 権威への非到達** | フレーバ出力は永続化されず、再注入されず、6D / profile / gap / tensor へ入らない | LAW-19 |
| **A-4 アンビエント** | UI もゲームも LLM を待たない。タイムアウトは既定への復帰であってエラーではない | SPEC_BLACKBOX §14 / §3.4-9 |
| **A-5 型による遮断** | 権威データ型はフレーバ層へ**渡せない**。渡せるのは `template_id` と量子化済み slot のみ | 壁 W-a / W-b / AI_SKILLS §4.57 |
| **A-6 リプレイ純度** | リプレイ・監査時にフレーバを再生成しない。決定論の再現にフレーバは関与しない | 第八律 / リプレイ恒等性 |

**A-2 の作法**: ガード不通過時に LLM へ再生成させる設計を**禁ずる**。再試行は検証器の穴を探索する行為であり、通過してしまった歪んだ出力が最も危険である。**破棄 → 固定テンプレート**の一択。

## 3. 境界防衛機構 — 型と構造による隔離

### 3.1 中核思想

**Parse, don't validate.** 検査を「関数を呼んだか」ではなく「**型を持っているか**」で保証する。検査を通った証明を型が運ぶ。

### 3.2 入力の封印（Rust）

- `SlotValue` は private field を持つ newtype。構築経路は `from_quantized(value_micro, unit)` と `from_enum(tag)` のみ
- **`From<String>` / `From<&str>` を実装しない**。これが壁である
- 権威型（`BlackboxProfile` / `TensorProfileReportV1` / `GenesisRequest` / vault row 等）に対して `Into<SlotValue>` を実装しない。「書かない」ではなく「書けば契約テストが落ちる」形にする
- `TemplateId` / `SlotId` は閉じた enum。文字列 ID を受け付けない

> **FLV-W-02**: `SlotValue` / `FlavorText` に `#[derive(Deserialize)]` を安易に付けると、serde が private field を迂回して構築でき、封印が破れる。→ §7 特務課題 G-2

### 3.3 出力の封印（Rust）

- `FlavorText` は private field を持つ newtype。**唯一の構築経路は `flavor_guard::verify(raw, &allowlist) -> Option<FlavorText>`**
- ガードを通らずに `FlavorText` は作れない。したがって「検査を忘れた経路」がコード上存在し得ない
- UI へ渡せるのは `FlavorText` のみ、と型で宣言する

### 3.4 モジュール境界

`llm/flavor/` は `db` / `analytics` / `blackbox_sim` の内部型を import しない。依存方向は「呼び出し側 → flavor」の一方向のみ。BXS-I-26 と同型の allowlist 走査で機械的に固定する。

### 3.5 FE 側（TypeScript）

- `FlavorText` は branded type とし、生成できるのは `parseFlavorResponse()` のみ
- FE はフレーバを**表示専用スロット**にのみ描画する。**数値表示は必ず Fact 側の view model から取る**
- フレーバ文字列を `Number()` / `parseFloat` / 数値抽出正規表現へ通す経路を走査で禁止

> **FLV-W-03**: FE でフレーバから数値を再抽出すると、型の壁を迂回して非決定論的数値が権威側へ入る。

## 4. 入出力規約

### 4.1 FlavorRequest（Rust → LLM）

```
schema:     "flavor_request.v1"
templateId: TemplateId               （閉じた enum）
slots:      [{ id: SlotId, value: String }]   （SlotValue 由来のみ）
locale:     "ja"
maxChars:   u16                      （テンプレートごとの上限・FLV-R-5）
```

`#[serde(deny_unknown_fields)]`。fields=camelCase / variants=snake_case（AI_SKILLS §4.12a-2）。

### 4.2 FlavorResponse（LLM → Rust）

**プレーンテキストのみ。LLM に JSON を書かせない。** フレーバは構造を持たず、JSON 化は「パース失敗」という失敗モードを増やすだけである。`llm/schema.rs` の構造化出力は**抽出タスク**の作法であり、フレーバには適用しない。

### 4.3 flavor_guard の判定

1. **文字種**: 制御文字・URL・マークアップ・コードフェンスを含めば破棄
2. **長さ**: `maxChars` 超過で破棄（**切り詰めない** — 切り詰めは意味を変える）
3. **数値**: 出力中の全数値表現を抽出し、slot allowlist に含まれることを要求

> **FLV-W-04（CJK の穴）**: SPEC_BLACKBOX §14 の「全数字列が allowlist に完全一致」は半角アラビア数字しか想定していない。日本語では全角数字（２５００）・漢数字（二千五百 / 二〇二六）・序数（第3四半期）・割合（五割）・曖昧量化（倍増 / 半減）で数値を発明できる。素朴な `\d+` 抽出はこれらを素通りさせる。→ §7 特務課題 G-1

## 5. 失敗モードと縮退

| 事象 | 挙動 |
|---|---|
| モデル未ロード / feature 無効 | 固定テンプレート（**既定であり、エラーではない**） |
| タイムアウト | 固定テンプレート。UI にエラーを出さない |
| ガード不通過 | **破棄** → 固定テンプレート。再試行しない |
| LLM 例外 | 固定テンプレート。生エラーは `log::error!` のみ |

フレーバの失敗はユーザーにとって**非イベント**である。UI に失敗を表示する設計は A-1 の否定に等しい。

ただし**破棄率の内部計測は残す**。高止まりは「モデルが指示に従えていない」ことの検出であり、FLV-R-3 の判断材料となる。計測値は権威状態ではない（A-3 と矛盾しない）。

---

## 6. 決定論の保全（FLV-R-2）

- リプレイ時にフレーバを**再生成しない**
- フレーバ文字列を決定ログに**混ぜない**。混ぜれば `state_digest` が非決定論に汚染され、Phase 6-A で構築したリプレイ恒等性（`ReplayDivergence` による書込拒否）が意味を失う
- **永続化しない**（FLV-R-2）。vault のどのテーブルにもフレーバ列を作らない

| Phase | 内容 | 完了条件 |
